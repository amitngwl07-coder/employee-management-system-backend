# Employee Management System – Backend

A RESTful Employee Management System API built using **Java, Spring Boot, Spring Data JPA, and MySQL**. This backend provides employee management operations, server-side pagination, searching, sorting, filtering, and dashboard statistics.

## Features

- Create, retrieve, update, and delete employees.
- Automatically generate unique employee codes (E0001, E0002, etc.).
- Validate employee details and prevent duplicate email addresses.
- Server-side pagination and sorting.
- Search employees by employee code, name, email, or department.
- Filter employees by department and employment status.
- Retrieve employee dashboard statistics.
- Centralized exception handling with meaningful API error responses.
- Separate local and production configurations.
- Environment-based database credentials.

## Database Configuration

Create a MySQL database:

```sql
CREATE DATABASE employee_db;
```

Configure the following environment variables:

| Variable | Description |
|---|---|
| DB_URL | MySQL database connection URL |
| DB_USERNAME | MySQL username |
| DB_PASSWORD | MySQL password |

Example local configuration:

```text
DB_URL=jdbc:mysql://localhost:3306/employee_db
DB_USERNAME=root
DB_PASSWORD=your_mysql_password
```

Never commit actual database credentials to GitHub.

## Running the Application Locally

**Prerequisites**

- Java 21 or compatible configured JDK
- MySQL
- Git

**1. Clone the repository**

```bash
git clone https://github.com/amitngwl07-coder/employee-management-system-backend.git
```

**2. Navigate to the project**

```bash
cd employee-management-system-backend
```

**3. Configure database environment variables**

Set `DB_URL`, `DB_USERNAME`, and `DB_PASSWORD` in your environment.

**4. Run the application with the local profile**

Windows PowerShell:

```powershell
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=local"
```

**5. Access the API**

```text
http://localhost:8080/api/employees
```

## REST API Endpoints

Base URL: `/api/employees`

| Method | Endpoint | Description |
|---|---|---|
| GET | `/api/employees` | Retrieve employees with pagination |
| GET | `/api/employees/{id}` | Retrieve employee by ID |
| POST | `/api/employees` | Create a new employee |
| PUT | `/api/employees/{id}` | Update an employee |
| DELETE | `/api/employees/{id}` | Delete an employee |
| GET | `/api/employees/statistics` | Retrieve employee statistics |

### Pagination, Search and Filtering

The employee listing endpoint supports:

| Parameter | Description |
|---|---|
| page | Page number (zero-based) |
| size | Number of records per page |
| sortBy | Field used for sorting |
| direction | Sort direction (asc/desc) |
| search | Search by employee code, name, email, or department |
| department | Filter by department |
| status | Filter by ACTIVE or INACTIVE |

Example:

```http
GET /api/employees?page=0&size=10&sortBy=createdOn&direction=desc
```

Example with filters:

```http
GET /api/employees?page=0&size=10&search=john&department=IT&status=ACTIVE
```

### Create Employee Example

**POST** `/api/employees`

Request body:

```json
{
  "name": "John Smith",
  "email": "john@example.com",
  "department": "IT",
  "joiningDate": "2026-01-15",
  "status": "ACTIVE"
}
```

Employee code and database ID are generated by the backend.

## Employee Status

Supported employee statuses:

- `ACTIVE`
- `INACTIVE`

## Error Handling

The application includes centralized exception handling for scenarios such as:

- Employee not found.
- Duplicate email addresses.
- Invalid request data.
- Validation failures.

Example error response:

```json
{
  "message": "Employee email already exist: john@example.com"
}
```

## Production Configuration

The application supports a separate production profile.

Production configuration uses:

- Environment variables for database credentials.
- Hibernate schema validation.
- Disabled SQL logging.
- Disabled Open Session in View.
- Configurable server port.
